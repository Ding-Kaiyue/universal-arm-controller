# Universal Arm Controller - 技术概览

**本文档面向**：技术决策者、架构师、系统评估人员
**预期阅读时间**：5–8 分钟

---

## 1. 系统定位与目标

### 产品定位
- 通用工业机械臂控制系统（6–7 DOF）
- 支持离线规划、示教录制、轨迹重放
- 模块化架构，可替换核心组件

### 核心目标
- 工业级控制频率：100 Hz 执行（可调）
- 支持多控制模式：MoveJ、MoveL、MoveC、速度控制
- 示教轨迹平滑与动力学约束
- 模块可替换、驱动可适配

### 明确的非目标
- 闭环力控（仅开环力矩补偿）
- 在线避障重规划（离线规划为主）
- 硬实时控制（Linux 软实时）
- 多臂协同优化（基础支持）

## 2. 系统能力速览

| 维度 | 指标 |
|------|------|
| **执行频率** | 100 Hz（可调） |
| **控制延迟** | < 200 μs（单周期） |
| **轨迹规模** | < 100k 点（CSAPS 平滑阈值） |
| **支持自由度** | 6–7（当前验证6自由度） |
| **内存占用** | < 50 MB（单臂） |
| **实时性保证** | 软实时（无硬实时） |

---

## 3. 关键架构决策

系统的核心能力来自以下 4 个战略选择：

| 决策点 | 选型 | 理由 | 代价 |
|--------|------|------|------|
| **IK 求解** | TRAC-IK + 拓扑连续性保证 | 轨迹品质优先 | 维护成本中等 |
| **时间参数化** | TOTG（时间最优轨迹生成） | 工业级稳定、关键点平滑 | 不支持 jerk 最优 |
| **示教平滑** | CSAPS（立方样条） | C² 连续、离线计算 | 无自适应参数 |
| **架构风格** | 分层 + 插件化 | 可扩展、模块独立 | 初期设计复杂度高 |

→ 详见 [Developer Guide](../developer/README.md) 中的算法文档

| 模块 | 成熟度 | 说明 |
|------|--------|------|
| 轨迹执行 | **生产级** | 架构稳定、接口清晰 |

| 力控 | **未实现** | 明确不在当前范围 |

## 5. 适用 / 不适用场景

### 强烈推荐

- 工业示教 & 离线重放（喷涂、焊接、装配）
- 精密点位操作（高精度、低速）
- 轨迹复杂度低、精度要求高的任务

### 可用，有限制

- 中等复杂路径（受外部规划器限制）
- 轻量双臂协同（无全局同步优化）

### 不推荐

- 实时力反馈装配（无力控闭环）
- 高速在线避障（无实时规划）
- 柔顺接触作业（无交互力反馈）

## 6. 系统风险与实现特征

### 实现特征
- 轨迹执行通过 `std::chrono::steady_clock` 的绝对时间控制（`sleep_until`）
- 路径规划器提供轨迹质量保证
- 硬件驱动实现标准接口

### 主要风险

| 风险 | 影响 | 缓解 |
|------|------|------|
| 非硬实时抖动 | 最坏时延不可界定 | 充分测试、冗余设计 |
| 规划器性能 | 轨迹质量依赖外部库 | 选择合适的采样密度 |
| 库升级破坏 | MoveIt/TRAC-IK API 变化 | 版本固定、定期验证 |

## 7. 架构扩展能力

| 场景 | 影响范围 | 难度 |
|------|----------|------|
| 添加新控制模式 | 仅 Controller 层 | ⭐ 简单 |
| 替换 IK 算法 | Planning 接口 | ⭐⭐ 中等 |
| 更换硬件驱动 | Hardware 层隔离 | ⭐⭐ 中等 |
| 引入力控 | 需新增 Control 层 | ⭐⭐⭐ 复杂 |
| 引入在线规划器 | 需新增 Planning 组件 | ⭐⭐⭐ 复杂 |
