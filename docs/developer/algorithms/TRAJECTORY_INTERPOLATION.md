# 轨迹插值算法设计说明

> 本文档描述 Universal Arm Controller 系统中，轨迹处理层子模块"轨迹插值模块"的架构设计、系统集成方式与责任边界。

## 1. 功能定位与系统层角色

轨迹插值解决的核心问题是：**在给定轨迹的关键点（稀疏的关键点序列）基础上，使用光滑插值函数生成密集的轨迹点，供控制循环以固定频率（100Hz）执行**。

在系统架构中，轨迹插值属于 **轨迹处理层（Trajectory Processing Layer）** 的一个关键子模块。轨迹插值在系统内的角色是：

- **为轨迹执行提供密集采样**：TOTG 生成的是稀疏关键点序列，插值为 100Hz 采样的密集轨迹
- **保证轨迹平滑性**：使用立方样条提供 $C^2$ 连续的轨迹（位置、速度、加速度都连续）
- **支持实时查询**：在任意时间点快速查询位置、速度、加速度
- **验证约束合规**：检查生成的轨迹是否满足关节速度、加速度、加加速度约束
- **独立于规划策略**：不关心输入轨迹来自 TOTG、手动示教还是其他来源

### 1.1 适用范围声明

**本模块面向**："已给定关键点序列（含时间和速度信息）的密集采样和平滑化问题"。

**不适用于**：
- **实时动态调整**：轨迹一旦插值完成，不支持在执行过程中修改
- **非时间参数化轨迹**：要求输入必须包含时间戳信息
- **约束验证失败的补救**：若生成的轨迹违反约束，只报错不修复

**定位**：轨迹插值是 **路径后处理的密集采样阶段**，在规划线程中离线执行，为执行层提供 100Hz 适配的光滑轨迹。

> [!NOTE]
> 因此，本模块属于轨迹规划与执行之间的“确定性后处理层”，其核心目标是：
> 在不引入新的规划决策的前提下，将规划结果转化为控制层可直接执行的光滑时间轨迹。

## 2. 算法模型与关键设计选择

### 2.1 插值问题定义

给定：
- 关键点序列： $\{(\mathbf{q}_0, t_0, \dot{\mathbf{q}}_0), (\mathbf{q}_1, t_1, \dot{\mathbf{q}}_1), \ldots, (\mathbf{q}_N, t_N, \dot{\mathbf{q}}_N)\}$
  - 每个点包含：关节位置 $\mathbf{q}_i$、时间戳 $t_i$、速度 $\dot{\mathbf{q}}_i$
  - $N+1$ 个关键点， $0 \leq t_0 < t_1 < \cdots < t_N$
- 采样频率： $f = 100$ Hz，采样间隔 $\Delta t = 0.01$ s

求解：
- 密集轨迹点序列： $\{(\mathbf{q}(t), \dot{\mathbf{q}}(t), \ddot{\mathbf{q}}(t)) \mid t \in [t_0, t_N], \Delta t = 0.01\}$
- 共约 100 倍的点数增加（取决于 $t_N - t_0$ 的大小）

约束条件：
- **光滑性**：采用 $C^2$ 连续的立方样条（位置、速度、加速度都连续）；ttk592/spline 库支持多种插值方式（线性、古典立方样条 $C^2$、立方Hermite $C^1$），本系统配置使用 $C^2$ 连续的古典立方样条
- **关节速度约束**： $|\dot{q}_{i,j}(t)| \leq v_{\max,j}$
- **关节加速度约束**： $|\ddot{q}_{i,j}(t)| \leq a_{\max,j}$
- **加加速度约束**（可选）： $|\dddot{q}_{i,j}(t)| \leq j_{\max,j}$

### 2.2 架构级决策（Architectural Decision Record）

**决策**：采用 **ttk592/spline 库的立方样条插值**，通过 TrajectoryInterpolator 和 MoveItSplineAdapter 两层适配提供便利接口。

**为什么选择 ttk592/spline**：

1. **算法成熟且轻量**：ttk592/spline 是经过验证的 C++ 立方样条库，仅包含核心算法，无额外依赖
2. **灵活的插值方式**：支持多种插值类型（线性、古典立方样条 $C^2$、立方Hermite $C^1$）和边界条件（一阶导数、二阶导数、not-a-knot），可根据需求灵活配置
3. **灵活的边界条件**：支持 Hermite 边界条件（端点速度指定），与 TOTG 输出完美匹配
4. **导数计算能力**：一、二、三阶导数都可计算，支持完整的约束验证（速度、加速度、加加速度）
5. **计算高效**： $O(n)$ 复杂度的样条系数计算，支持快速插值和导数查询

**系统中的三层架构**：

- **第一层（底层算法库）**：ttk592/spline - 立方样条算法的核心实现
  - 支持多种样条类型：`LINEAR`（线性）、`CUBIC_SPLINE`（古典 $C^2$）、`CUBIC_HERMITE`（局部 $C^1$）
  - 灵活的边界条件设置：`FIRST_DERIVATIVE`、`SECOND_DERIVATIVE`、`NOT_A_KNOT`
  - 系统采用：样条类型为 `CUBIC_SPLINE`（ $C^2$ 连续），边界条件为 `SECOND_DERIVATIVE`（自然样条）

- **第二层（多关节适配）**：MoveItSplineAdapter
  - 针对多关节轨迹的适配层
  - 为每个关节创建独立样条曲线 `joint_splines_[j]`
  - 统一管理时间序列 `time_points_` 和关节名称 `joint_names_`
  - 提供 ROS2 消息格式的转换接口

- **第三层（高层 API）**：TrajectoryInterpolator
  - 用户对外的统一接口
  - 提供轨迹加载、插值、约束检验、实时查询等便利函数
  - 隐藏底层适配细节，呈现简洁的插值 API

**代价与权衡**：

- 每关节独立样条意味着维度耦合性低，但无法进行跨关节优化（如零空间任务）
- 古典立方样条（ $C^2$ ）比Hermite样条（ $C^1$ ）更光滑，但对关键点分布敏感
- 样条插值对关键点间隔有隐性要求（间隔过小可能导致振荡，过大可能导致欠拟合）
- 不提供单调性保证（样条可能在关键点间出现局部极值，需验证）

**架构判断**：该决策优先考虑 **工程简洁性和可维护性**。通过采用成熟的开源库并在其上构建合适的接口层，避免了重复造轮子，同时保持了系统的灵活性和清晰的职责分工。库的多样化支持（多种样条类型和边界条件）为未来的定制需求预留了扩展空间。

总体而言，该模块遵循“规划负责决策，插值负责确定性变换”的分层原则，避免在插值阶段引入新的优化或策略判断。

### 2.3 样条插值的数学形式

对每个关节 $j$，在时间区间 $[t_i, t_{i+1}]$ 上定义立方多项式：

$$q_j(t) = a_{i,j} + b_{i,j}(t - t_i) + c_{i,j}(t - t_i)^2 + d_{i,j}(t - t_i)^3$$

系数 $(a, b, c, d)$ 由以下条件确定：

1. **位置连续**： $q_j(t_i) = q_{i,j}$，$q_j(t_{i+1}) = q_{i+1,j}$
2. **速度匹配**： $\dot{q}_j(t_i^+) = \dot{q}_{i,j}$，$\dot{q}_j(t_{i+1}^-) = \dot{q}_{i+1,j}$（Hermite 边界条件）

这给出了 4 个方程求解 4 个未知数，样条唯一确定。

**$C^2$ 连续性说明**：
- 位置 $C^0$ 连续：样条在关键点处连续
- 速度 $C^1$ 连续：样条一阶导数在关键点处连续
- 加速度 $C^2$ 连续：样条二阶导数在关键点处连续（在边界条件允许的范围内）
- 三阶导数可能在关键点处不连续（这是立方样条的特性）

> [!NOTE]
> 本系统采用 Clamped Cubic Spline（带一阶导数边界条件的 C² 立方样条）：
在保证全局 $C^2$ 连续的同时，强制端点速度与 TOTG 输出一致。

## 3. 算法接口与对外契约

轨迹插值向轨迹执行层提供的接口定义如下：

> [!NOTE]
> **输入参数**：
> - `sparse_trajectory`: 稀疏轨迹（关键点序列）
>   - 关节位置、时间戳、速度信息齐全
> - `spline_config`: 样条配置（样条类型、边界条件、约束限制）
> - `target_dt`: 目标采样间隔（默认 0.01 s）
>
> **输出结果**：
> - `dense_trajectory`: 密集轨迹（100Hz 采样）
>   - 包含位置、速度、加速度，以及时间戳
> - `success`: 是否成功插值
> - `constraint_violations`: 若存在约束违反，列出违反的关节和时间点
>
> **不承诺的职责**：
> - 不修复约束违反（只检测和报告）
> - 不调整关键点（假设输入关键点已合法）
> - 不处理不连续的时间戳（要求严格递增）
> - 不支持动态轨迹修改

### 3.1 接口契约形式化

| 维度 | 约束条件 |
|------|--------|
| **输入轨迹** | 至少 2 个关键点；时间戳严格递增；所有关键点包含位置和速度 |
| **采样间隔** | 0.001 s ≤ target_dt ≤ 0.05 s；关键点间隔 ≥ 3×target_dt |
| **输出轨迹** | 点数 = $(t_N - t_0) / \Delta t + 1$；时间戳均匀分布；速度/加速度通过导数计算 |
| **约束检验** | 采样所有输出点；检查速度、加速度、jerk 三个约束；返回所有违反的点和关节 |
| **失败语义** | 插值失败时返回空轨迹；约束违反时返回警告但仍返回密集轨迹 |

## 4. 系统集成与数据流

### 4.1 集成点

轨迹插值在系统中的位置：

```
时间最优轨迹生成 (TOTG)
    ↓
稀疏轨迹（关键点 + 速度信息）
    ↓
轨迹插值器 (TrajectoryInterpolator)
    ├─ 创建立方样条（每关节一条）
    ├─ 生成密集采样点（100Hz）
    ├─ 计算速度和加速度
    └─ 验证约束合规
    ↓
密集轨迹（100Hz 采样）
    ↓
轨迹执行器 (TrajectoryExecutor)
    ↓
硬件驱动（MIT 模式电机控制）
```

### 4.2 关键依赖

| 依赖模块 | 功能 |
|--------|-----|
| **TimeOptimalTrajectoryGeneration** | 生成稀疏关键点和速度信息 |
| **HardwareManager** | 提供关节速度/加速度限制 |
| **RobotModel** | 获取 DOF 数量和关节信息 |

### 4.3 集成模式

从架构视角看，轨迹插值的集成具有以下特征：

- **同步离线计算**（Synchronous Offline Processing）：在规划线程中完成，不参与控制循环
- **单向数据流**：接收 TOTG 输出，生成执行层输入，无反馈循环
- **批量处理**：一次插值处理整条轨迹，不支持增量添加
- **约束检验**：生成完整密集轨迹后进行完整检验，失败返回全轨迹但标记违反

## 5. 约束处理与验证

### 5.1 约束检验机制

轨迹插值**生成密集轨迹后**进行约束检验，步骤如下：

1. **对所有输出点采样**
   - 在 $[t_0, t_N]$ 上以 $\Delta t$ 间隔采样所有输出点

2. **计算导数**
   - 速度： $\dot{q}_j(t) = q'_j(t)$（一阶导数）
   - 加速度： $\ddot{q}_j(t) = q''_j(t)$（二阶导数）
   - 加加速度（jerk）： $\dddot{q}_j(t) = q'''_j(t)$（三阶导数）

3. **检验约束**
   对每个关节 $j$：
   -  $|\dot{q}_j(t)| \leq v_{\max,j}$
   -  $|\ddot{q}_j(t)| \leq a_{\max,j}$
   -  $|\dddot{q}_j(t)| \leq j_{\max,j}$（若定义）

4. **报告结果**
   - 成功：返回密集轨迹
   - 失败：返回密集轨迹 + 违反列表（关节、时间、超限值）

### 5.2 失败处理策略

若轨迹插值的输出违反约束：

| 违反类型 | 处理方式 |
|---------|--------|
| 速度违反 | 记录警告，返回轨迹；执行层需降速或重新规划 |
| 加速度违反 | 记录错误，返回轨迹；提示规划器调整参数 |
| 基本数值错误（如 NaN）| 返回空轨迹，插值失败 |

**关键设计选择**：轨迹插值 **不修复** 约束违反，只检测和报告。若输入关键点合法（TOTG 保证），输出通常也满足约束。

## 6. 性能分析

### 6.1 计算复杂度

| 操作 | 复杂度 | 单次耗时（估计） |
|-----|-------|-----------|
| 样条系数计算 | $O(n_{\text{dof}} \cdot N)$ | 0.1-0.5 ms |
| 密集采样生成 | $O(n_{\text{dof}} \cdot M)$， $M = (t_N - t_0) / \Delta t$ | 1-5 ms |
| 约束检验 | $O(n_{\text{dof}} \cdot M)$ | 1-3 ms |
| **总计** | - | **< 10 ms** |

其中：
- $n_{\text{dof}}$ = 关节自由度（通常 6）
- $N$ = 关键点数（TOTG 输出，通常 10-50）
- $M$ = 输出密集点数（通常 100-500）

**结论**：即使对最长轨迹（10秒），插值也在 100ms 内完成，远小于规划阶段总耗时（100-500ms）。

### 6.2 场景测试

#### 场景 1：典型 MoveL（1m 直线）

**初始条件**：
- 路径长度：1 m
- TOTG 输出：30 个关键点，总耗时 3 s
- 采样间隔：0.01 s

**期望行为**：
- 输出点数：约 300 个
- 计算耗时：< 3 ms
- 轨迹平滑：位置、速度、加速度都连续
- 约束检验：全部通过

**验证方式**：
- 检查输出点数是否正确
- 绘制速度/加速度曲线，验证平滑性（ $C^2$ 连续）
- 对比相邻点间的差分（速度）和二阶差分（加速度）

#### 场景 2：短轨迹（关键点间隔小）

**初始条件**：
- TOTG 输出：100 个关键点，总耗时 0.5 s
- 采样间隔：0.01 s

**期望行为**：
- 样条不应显著过冲（Runge 现象）
- 速度、加速度约束仍满足
- 即使关键点密集，插值仍快速

**验证方式**：
- 检查插值曲线是否在相邻关键点间单调（或只有一个极值）
- 对比 TOTG 速度和插值速度，验证平滑度提升

#### 场景 3：低速特殊轨迹

**初始条件**：
- TOTG 输出：10 个关键点，但某些段速度很低
- 采样间隔：0.01 s

**期望行为**：
- 低速段应保持低速（不应加速）
- 样条应自动处理大的时间间隔差异

**验证方式**：
- 检查最小、最大速度与 TOTG 输出的一致性
- 验证加速度曲线的平滑性

## 7. 实时性能与调度约束

### 计算性能

- **插值耗时**：< 10 ms（对大多数轨迹）
- **约束检验耗时**：< 5 ms
- **内存占用**： $O(n_{\text{dof}} \cdot M)$ 浮点数（通常 < 20 KB）

### 非硬实时保证

系统运行在标准 Linux + ROS 2 环境，**不提供硬实时保证**：

- 无法保证计算延迟 < 1μs 级别
- **关键调度语义**：轨迹插值在规划线程中执行，完全离线，不占用 100Hz 控制循环

**设计约束：** 本模块禁止在插值过程中进行动态内存分配和阻塞调用，以避免对规划线程调度造成不确定影响。

**集成者责任**：轨迹插值是轨迹规划的一部分，在规划阶段（100-500ms）完成，完全不影响实时控制。

## 8. 责任边界与不承诺事项

### 8.1 本模块的职责

**明确承诺**：

1. **高效插值**：在 10ms 内完成密集采样
2. **平滑性保证**： $C^2$ 连续轨迹（位置、速度、加速度都连续）
3. **约束检验**：详细报告约束违反的位置和关节
4. **导数计算**：通过样条导数精确计算速度、加速度、加加速度
5. **离线执行**：不参与控制循环，不影响实时性
6. **灵活配置**：支持多种样条类型和边界条件（通过 SplineConfig 配置）

### 8.2 本模块不承诺

**明确不承诺**：

1. **约束修复**：若轨迹违反约束，不自动调整（只报告）
2. **动态修改**：轨迹一旦插值完成，不支持在执行中修改
3. **全局优化**：不做跨轨迹段的优化（每次独立插值）
4. **单调性保证**：不保证样条在关键点间单调（可能有局部极值）
5. **最优采样**：不自动调整采样间隔，使用固定的 `target_dt`
6. **硬实时性**：不提供微秒级的实时保证（在离线规划阶段运行）

### 8.3 与其他模块的职责分工

| 功能 | 本模块 | 其他模块 |
|-----|-------|--------|
| 稀疏→密集轨迹转换 | ✅ | - |
| 样条插值 | ✅ | - |
| 约束检验 | ✅ | - |
| 约束修复 | - | ✅ (规划层) |
| 轨迹执行 | - | ✅ TrajectoryExecutor |
| 动态调整 | - | ✅ (应用层) |
