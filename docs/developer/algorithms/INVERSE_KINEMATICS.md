# 逆运动学算法设计说明

> 本文档描述 Universal Arm Controller 系统中，算法层子模块"逆运动学模块"的架构设计、系统集成方式与责任边界。

## 1. 功能定位与系统层角色

逆运动学解决的核心问题是：**在末端执行器空间坐标（笛卡尔坐标系）给定的情况下，计算对应的关节角度配置，使得机械臂能够按照指定的末端路径（直线、圆弧等）进行运动**。

在系统架构中，逆运动学属于 **算法层（Algorithm Layer）** 的一个子模块。根据 [架构设计](../ARCHITECTURE.md#3-核心运行时组件) 第 3 章的描述，算法层的职责是：

> 提供纯数学计算能力（无业务逻辑）

因此，逆运动学在系统内的角色是：

- **为轨迹规划层（Trajectory Planning）服务**：提供末端位姿到关节角的计算接口
- **独立于控制模式**：不感知是 MoveL、MoveC 还是其他轨迹形式
- **独立于硬件实现**：不关心电机驱动协议或总线类型，仅提供纯数学结果
- **可完全替换**：若需要使用其他 IK 求解器或分析算法，可以直接替换该模块而不影响规划器逻辑

---

## 2. 算法模型与关键设计选择

> 本模块的设计目标是在保证规划时间可接受的前提下，为末端直线/圆弧运动提供鲁棒、拓扑连续的 IK 求解能力。

### 2.1 求解问题的数学定义

逆运动学求解的是以下方程：

$$T_{target} = F_K(q)$$

其中：
- $T_{target}$ 为目标末端位姿（位置 + 姿态，SE(3)群中的变换矩阵）
- $F_K(q)$ 为正向运动学函数，$q$ 为关节角度向量
- 求解目标：找到满足上式的 $q$ 值

**问题性质**：
- **非线性**：正向运动学是关于关节角的非线性函数
- **多解性**：对于 6 轴及以上机械臂，同一目标位姿可能有多个有效解（不同分支）
- **欠定性**：对于冗余机械臂（关节数 > 6），解空间无限
- **约束条件**：关节角必须在限位范围内，避免奇异点

### 2.2 设计选择：采用 TRAC-IK 库而非自实现

> [!NOTE]
> 本模块遵循一下设计原则：
> - 单点职责：仅负责单点 IK 求解
> - 上层控制连续性： 连续性由规划层保证
> - 时间可控优先于全局最优

**核心决策**：使用 **TRAC-IK（TRanslational & Rotational, Augmented with Cyclic, IK）** 库作为底层求解引擎，而不是自实现 IK 算法。

**为什么选择 TRAC-IK**：

1. **混合求解策略**：
   - 当可能时尝试分析解（存在闭式解）
   - 必要时使用数值优化（基于 NLopt 库的 SLSQP 算法）
   - 保证求解成功率高，且计算时间有界

2. **鲁棒的约束处理**：
   - 内置关节限位处理
   - 奇异点自动避免机制
   - 支持位置-姿态独立求解（仅位置 IK）

3. **可配置的求解策略**：
   - Speed：优先快速求解（5ms 内）
   - Distance：优化求解距离（拓扑连续性）
   - Manipulation1/2：针对机械臂操作优化

4. **业界标准**：广泛应用于 MoveIt2、ABB、KUKA 等工业平台

**代价与权衡**：

- 增加了外部依赖（trac_ik_lib、NLopt）
- 求解时间不确定（虽然有上界，但实际时间随问题难度变化）
- 无法保证全局最优解（仅保证局部最优或可行解）

### 2.3 TRAC-IK 求解策略的差异

TRAC-IK 提供三种可配置的求解策略，各自的优化目标和性能特性不同：

| 策略 | 优化目标 | 单次耗时 | 成功率 | 适用场景 |
|------|---------|--------|------|---------|
| **Speed** | 最快求解 | 1-3ms | 95-98% | 对时间敏感的交互式控制，容忍多次重试 |
| **Distance** | 最接近种子 | 2-5ms | 97-99% | 需要拓扑连续性且时间充足的轨迹规划 |
| **Manipulation1/2** | 操作灵巧度 | 3-8ms | 90-95% | 优先考虑机械臂可操作性的特殊应用 |

**策略详解**：

1. **Speed 策略（默认）**：
   - 求解逻辑：分析解 → KDL 数值求解 → NLopt SLSQP 任意一个成功即返回
   - 优点：速度最快，分支跳变率相对高但可用 `computeIKClosest()` 补偿
   - 缺点：容易在多个分支之间震荡，单次成功率偏低
   - 系统应用：5ms 超时

2. **Distance 策略**：
   - 求解逻辑：按求解距离（L2 范数）排序，返回最接近种子点的解
   - 优点：天然保证拓扑连续性，减少 `computeIKClosest()` 的重试负担
   - 缺点：需要完整尝试所有分支，耗时最长
   - 适用：轨迹规划有充足时间（> 100ms），对连续性要求极高

3. **Manipulation1/2 策略**：
   - 求解逻辑：通过 Jacobian 矩阵计算操作灵巧度，在求解分支中优选灵巧度高的解
   - 优点：优先避免奇异点附近的解，可操作性最好
   - 缺点：额外的 Jacobian 计算开销，拓扑连续性不保证，成功率最低
   - 适用：焊接、涂胶等需要精确操作角度的特殊应用

**系统设计选择：为什么采用 Speed + computeIKClosest() 而非 Distance**

系统当前采用 **Speed 策略 + computeIKClosest() 多重重试** 的组合方案，而不是直接使用 Distance 策略。原因如下：

1. **时间效率考量**：
   - Speed：1-3ms per attempt → MoveL 30-50 采样点 = 30-150ms 总规划时间
   - Distance：2-5ms per attempt → 同样规划 = 60-250ms 总规划时间
   - 用多次重试(O(1)开销)补偿分支问题，优于单点求解时间加倍(O(n))

2. **等效的拓扑连续性保证**：
   - Distance 策略：单点内选择最接近的分支
   - computeIKClosest() + Speed：多次尝试 + wrap_to_nearest + L2 距离选择
   - 实际效果：都返回与 seed_state 最接近的解，保证关节角光滑

3. **灵活的场景适应**：
   - MoveL 采用 5 次重试（满足直线精度需求）
   - MoveC 采用 10 次重试（应对圆弧上的困难点，如高曲率区）
   - 这种差异化配置比固定策略更高效

4. **架构清晰性**：
   - 单一求解策略 (Speed)，通过上层适配层 (computeIKClosest) 实现逻辑
   - 而非在算法层堆砌多个策略选项
   - 降低系统复杂度，维护责任清晰

## 3. 算法接口与对外契约

逆运动学向轨迹规划层提供的接口定义如下：

> [!NOTE]
> **输入参数**：
> - `target_pose`: 末端目标位姿（SE(3) 变换，含位置 [x,y,z] 和姿态四元数 [qx,qy,qz,qw]）
> - `seed_state`: IK 种子状态（初始关节角度猜测，用于引导求解方向）
> - `num_attempts`: 求解重试次数（可选，默认 5）
>
> **输出结果**：
> - `solution`: 解的关节角度向量（单位：弧度）
> - `success`: 求解是否成功（bool）
> - `iterations`: 求解所需迭代次数（用于性能监测）
>
> **不承诺的职责**：
> - 不关心求解结果如何被使用（只负责计算）
> - 不保证全局最优解（只保证局部可行解）
> - 不处理轨迹连贯性检查（由调用者负责种子点递推）
> - 不感知机械臂的物理约束（如碰撞检测）

这种设计保证了**算法层的纯粹性**：它就是一个数学求解模块，接收输入，返回计算结果。

- 确定种子点传递（保证拓扑连续性）

- 执行单点 IK 求解，基于 TRAC-IK 库和 KDL 链结构

- 不做任何关于轨迹形状或控制策略的决策

## 5. 求解策略与集成方式

> 本章描述逆运动学在直线与圆弧规划中的具体集成方式，重点说明采样策略、连续性保证机制与失败控制策略。

### 5.1 MoveL 直线运动：笛卡尔采样 + IK 逐点求解

**触发时机**：MoveL 控制器执行直线运动规划命令时

**执行方式**：

1. **获取起点**：读取硬件当前关节角，通过正向运动学计算末端当前位姿
2. **笛卡尔采样**：沿起点→目标点的直线，以固定间隔（默认 0.02m）采样多个中间点
3. **逐点 IK 求解**：
   - 对每个采样点调用 `computeIKClosest(target, seed, solution, num_attempts=5)`
   - 种子点：前一点的 IK 解，保证拓扑连续性
   - 多次重试：自动重试 5 次并选择最接近种子的解

4. **关键检测**：
   - **软跳跃检测**：相邻两点关节角变化 > 0.35 rad，标记进入奇异区域
   - **硬跳跃检测**：相邻点关节角变化 > 1.20 rad，中止规划（ABB 标准）
   - **限位检查**：确保每个解都在关节限位范围内

5. **时间参数化**：使用时间最优轨迹生成（TOTG）算法赋予轨迹时间和速度

**优点**：
- 末端轨迹严格为直线（笛卡尔空间采样）
- 单点求解超时明确（< 5ms），规划时间可预测
- 关节轨迹光滑（拓扑连续性保证）
- 拓展性好（采样间隔可调）

**代价**：
- 笛卡尔采样点多时，需多次 IK 求解（时间线性增加）
- 在奇异点附近，IK 求解可能失败，导致规划中止
- 采样间隔过小可能导致规划时间过长（> 500ms）

### 5.2 MoveC 圆弧运动：圆弧参数化 + IK 逐点求解

**触发时机**：MoveC 控制器执行圆弧运动规划命令时

**执行方式**：

1. **圆弧构造**：根据起点、中间点、终点三点定圆，或根据圆心与半径构造圆弧
2. **圆弧参数化**：沿圆弧曲线进行参数化采样
   - 采样点数：根据弧长动态计算（最小 10 点，采样间隔约 10mm）
   - 参数范围：0 到 1 之间的参数化（Bezier 曲线或弧长参数化）

3. **逐点 IK 求解**：
   - 对每个圆弧采样点调用 `computeIKClosest()`
   - 重试次数：10 次（比 MoveL 的 5 次更多，应对圆弧上的困难点）
   - 种子点递推：与 MoveL 相同，前一点的解作为下一点的种子

4. **关键检测**：
   - 同 MoveL 的跳跃检测和限位检查
   - 额外：圆弧曲率变化检测（识别进出奇异点的边界）

5. **时间参数化**：同样使用 TOTG 算法

**优点**：
- 末端轨迹严格为圆弧（曲线空间采样）
- 采样点数自适应（避免过度采样）
- 高重试次数（10 次）提高成功率

**代价**：
- 圆弧参数化增加了计算复杂度
- 在接近奇异点的圆弧上，IK 求解可能频繁失败
- 总规划时间可能超过 MoveL（因为采样点更多或重试次数更多）

## 6. 拓扑连续性保证机制(computeIKClosest)

### 问题场景

对于多解机械臂，同一目标位姿可能有多个 IK 解，分属于不同的**分支**（肘上/肘下、腕正/腕反等）。

连续轨迹规划中，如果不加处理，相邻采样点的 IK 求解可能从一个分支跳到另一个分支，导致关节角突变：

> [!NOTE]
> 关节 1 的期望路径：
>  1.57 → 1.64 → 1.71 → 1.78  （连续递增）
>
> IK 求解结果（无处理）：
>  1.57 → -4.64 → -4.71 → 1.78  （出现跳变）

原因：在 (1.71, -4.71) 处两个分支角度相同（差 2π）

### 解决方案：computeIKClosest

**算法流程**：

```
输入：target_pose, seed_state, num_attempts=5

最佳距离 ← ∞
最佳解 ← None

FOR attempt = 1 TO num_attempts:
    调用 IK 求解器：q_raw ← solve_ik(target_pose, seed_state)

    IF 求解失败:
        continue

    FOR 每个关节 i:
        q_normalized[i] ← wrap_to_nearest(q_raw[i], seed_state[i])
        // 通过加减 2π 倍数，将解映射到最接近种子的 2π 周期内

    distance ← L2_norm(q_normalized - seed_state)

    IF distance < 最佳距离:
        最佳距离 ← distance
        最佳解 ← q_normalized

输出：最佳解（保证与种子点拓扑连续）
```

**关键实现细节**：

1. **角度规范化**（wrap_to_nearest）：
   ```
   目标：找到 q_norm = q_raw + 2π·k 使得 |q_norm - q_ref| 最小

   实现：
     for k in [-2, -1, 0, 1, 2]:
         q_candidate = q_raw + 2π·k
         if q_candidate 在限位 [q_min, q_max] 内:
             if |q_candidate - q_ref| < 当前最小值:
                 q_norm = q_candidate
   ```

2. **L2 距离度量**：保证最接近的解不一定是某个轴上最接近的

3. **多次重试**：
   - TRAC-IK 的随机初始化：每次求解可能得到不同的解
   - 通过多次尝试，增加找到目标分支的概率

**效果**：
- 避免了分支跳变导致的关节角突变
- 保证连续轨迹的关节角曲线光滑
- 失败率低（对大多数规划问题成功率 > 95%）

## 7. 实时性能与调度约束

### 计算复杂度

- **时间复杂度**：O(n_attempts × t_solve)
  - n_attempts：重试次数（通常 5-10）
  - t_solve：单点求解时间（由 TRAC-IK 决定，一般 2-5ms）
- **空间复杂度**：O(n_joints)，主要用于缓存 KDL 链和中间结果

### 性能预期

基于目标硬件（标准 x86 或 ARM 多核处理器）：

- 单点 IK 求解（单次尝试）：**1-3ms**
- 多次重试（5 次）：**5-15ms**
- 整条 MoveL 规划（20-50 采样点）：**100-500ms**
- 整条 MoveC 规划（40-100 采样点）：**200-1000ms**
- 时间参数化（TOTG）：**< 100ms**

**性能预期**：
- 在 100-500ms 内完成典型 MoveL 规划（长度 1m）
- MoveC 规划时间通常是 MoveL 的 2-3 倍
- 不会成为实时控制循环的瓶颈（100Hz 定时器 = 10ms 周期）

### 非硬实时保证

系统运行在标准 Linux + ROS 2 环境，**不提供硬实时保证**：

- 无法保证单点求解延迟 < 1μs 级别
- 无法保证整体规划时间确定性
- **规划在 ROS 2 回调线程中同步执行**（~100-500ms），但不会阻塞 100Hz 控制循环，因为：
  - 控制循环在硬件驱动线程中独立运行
  - 轨迹规划使用 ROS 2 MultiThreadedExecutor 的独立回调线程
  - `execute_trajectory_async()` 返回后立即返回，执行在后台线程进行

**集成者责任**：IK 规划虽然是同步完成的，但由于使用独立线程，不会阻塞 100Hz 硬件控制循环。

## 8. 集成边界与责任划分

### 算法模块不负责的事项

- 不处理 URDF 模型的加载失败恢复（由 MoveIt 适配层负责）
- 不验证输入位姿的可达性（由规划器负责检查）
- 不处理碰撞检测（属于轨迹验证阶段）
- 不知道计算结果如何被使用
- 不处理并发访问的同步

### 规划层必须负责的事项

- 确保种子点合理（避免差距过大导致求解困难）
- 处理 IK 失败情况（重试、调整采样密度、或报错）
- 进行轨迹连贯性检查（关节跳跃、奇异点检测）
- 维护采样点序列的连续性
- 在规划失败时向上层报告原因

### MoveIt 适配层的职责

- 负责 URDF 模型加载和 KDL 链构建
- 负责初始化 TRAC-IK 求解器实例
- 提供关节限位信息
- 缓存已加载的模型和求解器，避免重复初始化

## 9. 典型使用语义与验证期望

逆运动学的实现应满足以下典型场景的行为预期：

### 场景 1：直线运动到达目标位置

**期望行为**：用户指定末端目标位姿，机械臂沿直线到达，且关节角变化平滑。

**工作机制**：
- MoveL 规划器对直线进行笛卡尔采样（0.02m 间隔）
- 对每个采样点调用 IK 求解
- computeIKClosest 确保相邻采样点的 IK 解拓扑连续
- TOTG 赋予轨迹平滑的时间和速度参数

### 场景 2：圆弧运动（焊接或涂胶）

**期望行为**：机械臂沿圆弧轨迹运动，末端工具轨迹严格为圆弧，关节轨迹光滑。

**工作机制**：
- MoveC 规划器对圆弧进行参数化采样
- 采样点更密集，IK 重试次数更多（10 次）以提高成功率
- 在圆弧高曲率区（接近奇异点）可能失败，此时规划器报错或调整采样

### 场景 3：IK 求解失败处理

**期望行为**：当某个位姿无 IK 解时，规划器及时检测并报错，而不是返回错误的关节角。

**工作机制**：
- 若 computeIKClosest 重试 5-10 次仍失败，返回失败标志
- 规划器收到失败信号，中止当前轨迹规划
- 向上层控制器报告"规划失败"，由应用层处理

## 10. 高级特性：关节限位与奇异点处理

### 10.1 关节限位与拓扑连续性的角度包裹

问题：TRAC-IK 返回的解可能超出关节限位 [q_min, q_max]，且为保证拓扑连续性需要通过 ±2π 映射到最接近前一采样点的角度表示。

**两层处理机制**：

**第一层（computeIKClosest）**：对 IK 求解结果进行拓扑归一化，通过 ±2π 偏移将其映射到最接近种子点的等效角度表示，保证相邻采样点的光滑过渡。

**第二层（wrapToNearest）**：在硬限位约束下二次包裹。若第一层结果超限，尝试其他 2π 倍数偏移（k = ±1, ±2, ±3）以找到限位内的解。若全部尝试失败则返回 NaN。

**两层的必要性**：
- TRAC-IK 多次求解可能返回不同分支的等效解（q 与 q ± 2π）
- 第一层优先保证与种子点同一分支（拓扑连续性）
- 第二层在必要时尝试其他分支（容错机制）

**效果**：
- 相邻采样点关节角光滑变化（无 2π 跳跃）
- 多圈旋转能力
- 限位内的物理可行解

### 10.2 奇异点检测与处理

**奇异点的表现**：
- 雅可比矩阵行列式接近零
- IK 求解耗时突增（接近超时 5ms）
- 相邻采样点关节角跳跃大（> 0.35 rad）

**检测机制**：
```
if (||q_current - q_previous|| > SOFT_JUMP):
    mark_singular_region() // 后续采样点降低接受阈值或增加采样密度

if (||q_current - q_previous|| > HARD_JUMP):
    abort_planning()  // 中止规划，返回错误
```

**应对策略**：
- 软阈值（0.35 rad）：标记进入奇异区域，提示但不中止
- 硬阈值（1.20 rad）：直接中止，避免危险的关节运动
